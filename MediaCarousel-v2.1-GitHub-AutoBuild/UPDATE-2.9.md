# MediaCarousel 2.9 · 結束動作與影片切換預載

中央主音量旁「播放及輸出 ▾」新增明確的「播放結束後」選項：停留最後一幀，或消失（清空影像）。這會在播放一次的清單或單一 CUE 結束時生效，循環模式仍繼續輪播。單畫面消失後露出黑色畫布；多畫面清除該格影像與底色，露出下層內容，其他格子繼續播放。再次播放會恢復格子底色與內容。

設定可隨專案、自動保存與 CUE 記憶。相容舊版 hold_last 布林設定，新版明確 end_action 值優先。圖片、影片與 PDF 使用同一結束策略；PowerPoint 原生放映維持原生控制流程。

## 切換卡頓原因與修正

原流程等到切換當下才打開影片並等待首幀，單畫面直接切換的單檔循環也重載來源。新增使用既有備用播放器的預載：隱藏畫面、零音量，在剪輯起點的有效首幀準備好後暫停；切換時沿用已準備的播放器，不重新 setSource。未準備完成或快取失效時沿用正常載入流程，保留舊畫面等待新來源就緒。

最多保留兩個預載來源，同時只啟動一個預載解碼；多畫面僅在片尾前兩秒準備下一支影片。預載錯誤不會停止正在播放的來源；改變檔案、剪輯起點／終點、來源順序或模式會檢查快取，失敗後正常載入。直接切換的單檔循環沿用目前播放器回到剪輯起點。

另修正同一 URL 重複使用時，Qt 不一定再發出 LoadedMedia 通知，導致首幀準備等待的問題；剪輯起點設定完成前不進行轉場，舊的延遲回呼也需符合載入代次。

不重新編碼影片，不改變來源解析度、播放幀率、畫布、滿版方式、平滑縮放或使用者選定的轉場效果。

## 驗證

本機 Linux／Qt 6.8.3 軟體顯示測試，以兩個 1080p30 H.264/AAC 檔案各執行六次直接切換，包含等待首幀、預覽繪製與中心像素讀回，切換耗時中位數由 25.35 ms 降至 13.43 ms，約減少 47%。這是單次指定條件測試，不代表所有影片或電腦的固定改善比例；高解析度、多路輸出及其他編碼仍受硬體限制。

回歸測試涵蓋有效剪輯首幀、六次同檔案來源循環不重設 setSource、改變起點失效重載、預載錯誤隔離、兩個多畫面快取上限、沒有列表增長、原始檔 SHA256 不變、最後一幀／透明消失、舊設定遷移與 CUE／專案保存。原有畫布、滿版、PDF、簡報、FADER 與 16 種介面搭配亦保留。

三種原生安裝包的建置檢查會實際解碼內建合成 H.264/AAC 測試片，驗證靜音預載、切換不重載及兩種結束策略，並執行既有 PDF、PCM 音量表及 Windows PowerPoint 元件檢查。
